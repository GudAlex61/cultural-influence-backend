# «Культурный след» — лабораторная работа № 2

SSR-приложение на NestJS, TypeScript, Handlebars, TypeORM и PostgreSQL. Предметная сущность `artwork_excerpts` — отрывки произведений искусства для расчёта культурного влияния по цитированиям.

Оформление частично основано на [странице театров «Культура.РФ»](https://www.culture.ru/theaters): используются цвета `#3C3C3C`, `#FFFFFF`, `#ED2324`, серая панель, крупные изображения с затемнением, скруглённые карточки и hover-эффекты.

## Запуск

Требуются Node.js, npm и Docker Desktop.

### Первый запуск

```bash
npm install
docker compose up -d
npm run migration:run
npm run start:dev
```

### Повторный запуск

```bash
docker compose up -d
npm run migration:run
npm run start:dev
```

Повторный `migration:run` безопасен: TypeORM применяет только ещё не выполненные миграции. Не используйте `docker compose down -v`, если хотите сохранить базу данных и загруженные в MinIO файлы.

- приложение: `http://localhost:3000/artwork_excerpts`;
- Adminer: `http://localhost:8081`;
- MinIO: `http://localhost:9001`.

Подключение в Adminer:

- система: `PostgreSQL`;
- сервер: `postgres`;
- пользователь: `cultural_user`;
- пароль: `cultural_password`;
- база данных: `cultural_influence`.

На компьютере PostgreSQL-контейнер доступен по порту `5455`, потому что стандартный порт `5432` занят локальной службой PostgreSQL.

### Восстановление после демонстрации удаления

Удаление карточки в приложении логическое: строка остаётся в БД, а поле `status` принимает значение `deleted`. Для повторного показа не нужно откатывать миграцию. В Adminer откройте «SQL-команда» и выполните, подставив ID удалённой карточки:

```sql
UPDATE artwork_excerpts
SET status = 'published'
WHERE id = 1 AND status = 'deleted';
```

Полный сброс нужен только для возврата всей демонстрационной БД к исходному состоянию. Он удалит все сделанные в БД изменения:

```bash
npm run migration:revert
npm run migration:run
```

## Структура БД

Миграция создаёт ровно три предметные таблицы без каскадного удаления:

- `artwork_excerpts` — отрывки произведений искусства;
- `users` — пользователи;
- `artwork_excerpt_likes` — связь многие-ко-многим пользователей и отрывков.

Для лайков задан составной уникальный ключ `user_id + artwork_excerpt_id`. Частичный уникальный индекс разрешает каждому пользователю не более одного отрывка в статусе `draft`.

Два тематических поля `artwork_creation_date` и `citation_count` допускают `NULL`, пока карточка является черновиком. URL изображения и видео обязательны. Новая карточка получает URL локальных файлов по умолчанию `/media/default-artwork.jpg` и `/media/default-artwork.mp4`; выбранные в браузере файлы в ЛР2 не отправляются на сервер и не сохраняются в БД.

Схема и исходные демонстрационные данные создаются миграцией `src/database/migrations/1726848000000-InitialDatabase.ts`. Числовой префикс — стандартный timestamp TypeORM, который задаёт порядок применения миграций; файл должен храниться в репозитории. Автоматическое изменение схемы отключено: `synchronize: false`.

## Обработчики ЛР2

Пять операций выполняются через TypeORM:

- `GET /artwork_excerpts/feed/:id?next=true` — одна строка ленты;
- `GET /artwork_excerpts/draft` — текущий черновик или первый этап добавления;
- `GET /artwork_excerpts?artworkCreationDate=1866-01-01` — плитка с серверной фильтрацией;
- `POST /artwork_excerpts` — создание черновика;
- `POST /artwork_excerpts/:id/publish` — публикация черновика.

Логическое удаление выполняется без ORM прямым SQL-запросом `UPDATE`:

- `POST /artwork_excerpts/:id/delete`.

Запрос ленты использует `LIMIT 1` через TypeORM `getOne()` и не загружает всю таблицу в массив. Удалённые записи не отображаются и недоступны по URL.

## Порядок показа ЛР2

1. В Adminer изменить `status` карточки на `deleted`, затем показать результат `SELECT`.
2. В приложении показать плитку, фильтр календарём, логическое удаление и `404` по URL удалённой карточки.
3. На странице добавления выбрать фото и видео, ввести название и нажать «Далее». Показать в БД новый `draft`: URL заполнены локальными значениями, описание и два тематических поля равны `NULL`.
4. Заполнить краткое описание, `artwork_creation_date`, `citation_count`, нажать «Опубликовать» и показать новую строку через `SELECT`.
5. Через Adminer изменить два тематических поля и количество строк в `artwork_excerpt_likes`, затем показать изменения в приложении.
6. В коде показать три entity-модели, пять ORM-операций и отдельное удаление через сырой SQL `UPDATE`.
7. В HTML страницы добавления показать локальные фото и видео по умолчанию.
8. Открыть `documentation/cultural-influence.drawio`: ровно три таблицы, PK/FK, типы и длины, сплошные связи, без сетки и внешней рамки.
