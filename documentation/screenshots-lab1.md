## Скриншоты 8–9: источник стилистики

- [ ] **08-culture-reference.png** — открытая страница популярного тематического ресурса «Культура.РФ», на которой видны выбранные элементы визуального стиля.
- [ ] **09-borrowed-css.png** — рядом или последовательно показаны источник и отдельный CSS-файл приложения. В CSS видны три точных базовых цвета `#ED2324`, `#3C3C3C`, `#FFFFFF`, форма карточек и правило `:hover`. Дополнительные визуальные оттенки создаются прозрачностью этих цветов.

Фраза для объяснения:

> В качестве тематического визуального аналога выбран портал «Культура.РФ», посвящённый литературе, кино и другим видам искусства. Использованы три базовых цвета `#ED2324`, `#3C3C3C`, `#FFFFFF`, контрастная редакционная типографика, крупные медиа, короткие рубрики над заголовками, карточная подача, тонкие разделители и реакция карточки при наведении. Логотип и название ресурса не копируются. Структура трёх экранов выполнена по заданию лабораторной.

Источники для показа: тематический портал `https://www.culture.ru/` и официальный брендбук `https://pro.culture.ru/documentation/brand-book-pro.pdf`.

Не следует говорить, что сайт скопирован целиком: повторяются только перечисленные признаки стилистики.

## Скриншоты 10–12: три страницы и три GET-запроса

Перед съёмкой открыть DevTools → `Network`, очистить список запросов и обновить нужную страницу. В кадре должны одновременно читаться страница, метод `GET` и URL запроса.

- [ ] **10-get-feed.png** — лента и запрос `GET /artwork-excerpts/feed/1?next=true`. Объяснить: `1` — ID текущего отрывка, `next=true` просит обработчик найти следующий опубликованный отрывок. Дополнительно можно показать `/artwork-excerpts/feed` как тот же обработчик без ID для панели вкладок.
- [ ] **11-get-draft.png** — страница добавления и запрос `GET /artwork-excerpts/draft`. Объяснить: сервер выбирает единственную запись со статусом `draft`; заполнение формы не отправляет данные.
- [ ] **12-get-gallery-filter.png** — плитка после поиска и запрос `GET /artwork-excerpts?publicationYear=1866`. Объяснить: `publicationYear` — числовой query-параметр серверной фильтрации; значение `1866` сохранилось в input после ответа.

Проверить до съёмки: в плитке нет записей `draft` и `deleted`; прямой переход из карточки содержит ID; кнопка «Следующий» действительно меняет опубликованный отрывок.

## Скриншоты 13–17: MinIO, коллекция и три шаблона

- [ ] **13-response-minio-urls.png** — вкладка `Response` для HTML-страницы отрывка; в исходном HTML видны полный URL изображения (`poster`/`img src`) и URL видео (`video src`) из MinIO. Если строки далеко друг от друга, использовать поиск внутри Response и сделать читаемый кадр.
- [ ] **14-model-object-keys.png** — коллекция `ArtworkExcerpt` в коде; у одной или нескольких записей видны два раздельных латинских ключа `imageObjectKey` и `videoObjectKey`, а также место формирования полного URL MinIO.
- [ ] **15-template-feed-minio.png** — шаблон ленты; видны использование URL изображения и видео в HTML.
- [ ] **16-template-draft-minio.png** — шаблон добавления; видно использование изображения выбранного черновика и отдельные поля изображения и видео.
- [ ] **17-template-gallery-minio.png** — шаблон плитки; видно, что каждая карточка получает собственный URL изображения из переданного элемента коллекции.

Во время объяснения отдельно сказать: ключи объектов записаны латиницей; изображение и видео хранятся в модели в разных полях; медиа находятся в MinIO, а не в локальной папке приложения.

## Скриншоты 18–19: маршрутизация и обработчики

- [ ] **18-three-routes.png** — код контроллера, где одновременно видны три GET-обработчика: лента по необязательному ID, черновик, плитка. Если код не помещается, уменьшить масштаб редактора, но сохранить читаемость.
- [ ] **19-filter-controller.png** — тело обработчика плитки и связанная логика: выбор только `published`, фильтрация по `publicationYear`, вычисление `likeCount` по `likedByUserIds.length`, возврат введённого значения в шаблон. По возможности в том же кадре показать логику ID и `next=true` либо переключиться на неё во время устного показа без дополнительного обязательного скриншота.

Фраза для объяснения:

> В приложении три GET-обработчика и одна коллекция. Контроллер получает path- и query-параметры, выбирает данные из массива, вычисляет производные значения и передаёт объект представления в Handlebars. Запросы ничего не изменяют, базы данных и клиентского JavaScript в первой лабораторной нет.
