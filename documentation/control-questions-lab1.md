# Ответы на контрольные вопросы лабораторной работы № 1

## 1. Что такое MVT

MVT — архитектурный шаблон **Model–View–Template**.

- **Model** хранит структуру и правила работы с данными.
- **View** принимает HTTP-запрос, получает и подготавливает данные, выбирает шаблон и формирует ответ. В терминологии MVT эта часть выполняет роль обработчика.
- **Template** задаёт представление HTML и вставляет в него переданные значения.

Пользователь запрашивает URL, View обращается к Model, передаёт результат в Template, после чего сервер возвращает готовый HTML. MVT часто связывают с Django: то, что Django называет View, по ответственности близко к Controller в MVC.

## 2. Какие компоненты MVC есть в лабораторной работе

MVC — архитектурный шаблон **Model–View–Controller**.

- **Model** — интерфейс `ArtworkExcerpt` и коллекция отрывков. Поля модели: `id`, `workTitle`, `excerptText`, `creatorName`, `publicationYear`, `workType`, `status`, `imageObjectKey`, `videoObjectKey`, `likedByUserIds`.
- **View** — шаблоны Handlebars для ленты, добавления и плитки, общий нижний блок навигации и отдельный CSS-файл.
- **Controller** — контроллер NestJS с тремя GET-обработчиками. Он выбирает опубликованный отрывок по ID, переходит к следующему при `next=true`, получает черновик, фильтрует плитку по году и вычисляет количество лайков.

Поток данных в лабораторной:

`браузер → HTTP GET → NestJS Controller → массив ArtworkExcerpt → данные шаблона → Handlebars View → HTML-ответ`.

Отдельный Service-слой и база данных в первой лабораторной не требуются. Добавлять их только ради усложнения не нужно.

## 3. Что такое шаблонизация

Шаблонизация — формирование документа по шаблону и данным. В `.hbs`-файле записана постоянная HTML-разметка и выражения Handlebars, например вывод поля, условие или перебор коллекции. NestJS передаёт объект данных в шаблон, Handlebars подставляет значения, а браузер получает уже сформированный HTML.

Виды шаблонизации:

- серверная — HTML формируется на сервере до отправки браузеру;
- клиентская — интерфейс строится JavaScript-кодом в браузере.

В лабораторной используется серверная шаблонизация Handlebars. Клиентский JavaScript запрещён. Повторяющиеся части можно вынести в partial, например нижнюю навигацию.

Важно: Handlebars по умолчанию экранирует специальные HTML-символы, что уменьшает риск внедрения разметки из данных. Тройные фигурные скобки следует применять только для заранее проверенного содержимого.

## 4. Что такое HTTP и как он связан с моделью OSI

HTTP — прикладной протокол обмена сообщениями между клиентом и сервером. Клиент отправляет запрос с методом, URL, заголовками и при необходимости телом. Сервер возвращает статус, заголовки и тело ответа.

Пример запроса лабораторной:

```http
GET /artwork-excerpts?publicationYear=1866 HTTP/1.1
Host: localhost:3000
```

В нём:

- `GET` — метод чтения ресурса;
- `/artwork-excerpts` — путь;
- `publicationYear=1866` — query-параметр фильтра;
- `Host` — заголовок с именем и портом сервера.

GET считается безопасным методом, потому что предназначен для чтения, и идемпотентным: повторение одинакового запроса не должно изменять состояние сервера. В первой лабораторной все операции являются просмотром, поэтому используются GET-запросы.

В семиуровневой модели OSI HTTP относится к прикладному уровню 7. При обычной передаче он использует транспортный протокол TCP уровня 4, TCP передаётся через IP уровня 3, а кадры локальной сети относятся к канальному уровню 2. Физический уровень 1 передаёт биты. TLS для HTTPS обеспечивает шифрование поверх транспорта; на практике стек Интернета описывают моделью TCP/IP, а OSI используют как учебную модель разделения функций.

Типовые коды состояния:

- `200 OK` — запрос успешно выполнен;
- `302 Found` — перенаправление;
- `400 Bad Request` — некорректный запрос;
- `404 Not Found` — ресурс не найден;
- `500 Internal Server Error` — внутренняя ошибка сервера.

## 5. Что такое Web

World Wide Web — распределённая система связанных ресурсов и веб-приложений, доступных по URL через протоколы HTTP/HTTPS. Web работает поверх Интернета, но не равен Интернету: Интернет является сетевой инфраструктурой, а Web — одной из использующих её служб.

Основные части Web:

- браузер как HTTP-клиент;
- веб-сервер или веб-приложение;
- URL для адресации ресурсов;
- HTTP/HTTPS для обмена;
- HTML для структуры документа;
- CSS для оформления;
- JavaScript для поведения, если он нужен.

В лабораторной браузер запрашивает страницу по URL, NestJS обрабатывает маршрут, Handlebars формирует HTML, а медиафайлы браузер получает из публичного бакета MinIO по отдельным URL.

## 6. Что такое HTML

HTML — язык гипертекстовой разметки, который описывает структуру веб-документа. HTML не является языком программирования: в нём нет общей модели вычислений, а элементы обозначают смысл и структуру содержимого.

Документ состоит из элементов, атрибутов и текста. Браузер разбирает HTML и создаёт объектную модель документа DOM. CSS применяет к элементам правила оформления.

Примеры используемых элементов:

- `<main>`, `<nav>`, `<article>` — семантическая структура;
- `<h1>`, `<p>` — заголовок и абзац;
- `<img>` — изображение;
- `<video autoplay muted loop playsinline>` — автоматически проигрываемое вертикальное видео;
- `<form method="get">` и `<input>` — серверная фильтрация;
- `<a>` — переход между GET-страницами;
- `<details>` и `<summary>` — раскрытие текста «больше/меньше» без JavaScript.

Атрибут `alt` у изображения содержит текстовую альтернативу. Семантические элементы и корректные подписи полей улучшают доступность и понятность документа.

## Короткое сопоставление терминов

| Вопрос | Ответ применительно к лабораторной |
|---|---|
| Где хранятся данные? | В одном массиве `ArtworkExcerpt`, без БД |
| Кто принимает запрос? | GET-обработчик контроллера NestJS |
| Кто формирует HTML? | Handlebars на сервере |
| Что получает браузер? | Готовый HTML и ссылки на CSS/медиа |
| Где находятся изображения и видео? | В публичном бакете MinIO |
| Почему нет JavaScript? | Все переходы и фильтрация выполняются обычными GET-запросами, раскрытие текста — HTML-элементом `details` |
