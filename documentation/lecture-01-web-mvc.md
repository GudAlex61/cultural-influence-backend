# Конспект лекции 1. История Web и MVC

Этот текст — краткая опорная версия по теме лекции. Для допуска преподаватель может потребовать собственный рукописный или оформленный студентом конспект.

## 1. Интернет и Web

Интернет — глобальная система связанных компьютерных сетей, работающая на основе семейства протоколов TCP/IP. Web, или World Wide Web, — одна из служб Интернета. Он предоставляет доступ к связанным документам и приложениям по URL через HTTP/HTTPS.

Интернет существовал до Web. Кроме Web его используют электронная почта, передача файлов, системы обмена сообщениями и другие сетевые службы.

## 2. Возникновение Web

Предпосылками Web стали развитие пакетной передачи данных, сетей ARPANET, стека TCP/IP и гипертекста. В конце 1980-х Тим Бернерс-Ли в CERN предложил систему связанных документов. Базовыми технологиями стали:

- URL/URI — адрес ресурса;
- HTTP — протокол запроса и ответа;
- HTML — разметка гипертекстового документа;
- браузер и веб-сервер — клиентская и серверная программы.

Появление графических браузеров упростило массовое использование Web. Далее статические страницы дополнились серверной генерацией HTML, базами данных и клиентскими сценариями. Современный Web включает как обычные документы, так и сложные веб-приложения.

## 3. Клиент-серверное взаимодействие

1. Пользователь вводит URL или нажимает ссылку.
2. Браузер определяет адрес сервера и устанавливает сетевое соединение.
3. Браузер отправляет HTTP-запрос.
4. Сервер выбирает обработчик, получает или вычисляет данные.
5. Сервер возвращает HTTP-ответ, например HTML.
6. Браузер разбирает HTML, загружает CSS и медиа и отображает страницу.

URL может включать схему, имя узла, порт, путь, query-параметры и фрагмент. Например, в `http://localhost:3000/artwork-excerpts?publicationYear=1866` схема — `http`, узел — `localhost`, порт — `3000`, путь — `/artwork-excerpts`, параметр — `publicationYear=1866`.

## 4. Статические и динамические страницы

Статический файл сервер отдаёт почти без изменения. Динамическая страница формируется для запроса из шаблона и данных. В лабораторной Handlebars на сервере получает объект от NestJS и создаёт HTML для конкретного отрывка или набора карточек.

Серверный рендеринг позволяет получить готовую страницу без выполнения клиентского JavaScript. Это соответствует требованиям лабораторной № 1.

## 5. Архитектурный шаблон MVC

MVC разделяет приложение на три ответственности:

- **Model** — данные и правила предметной области;
- **View** — представление данных пользователю;
- **Controller** — приём действий пользователя, выбор операции и подготовка ответа.

Разделение уменьшает связанность частей программы: представление можно менять без изменения структуры данных, а обработку запроса — без переписывания всей HTML-разметки.

В проекте «Культурный след»:

- Model — `ArtworkExcerpt` и массив отрывков;
- View — шаблоны Handlebars и CSS;
- Controller — три GET-обработчика NestJS.

## 6. MVT и его отличие от MVC

В MVT используются Model, View и Template. Template отвечает за разметку, а View получает запрос и подготавливает данные. Главное отличие часто находится в названиях и распределении ответственности: MVT View близка к MVC Controller, а MVT Template близок к MVC View.

Оба подхода нужны для разделения данных, обработки и отображения.

## 7. Основные термины

- **Гипертекст** — текст со ссылками на другие части или ресурсы.
- **Гиперссылка** — элемент, содержащий адрес перехода.
- **Браузер** — клиент для получения и отображения веб-ресурсов.
- **Веб-сервер** — программа, принимающая HTTP-запросы и возвращающая ответы.
- **URL** — адрес ресурса.
- **HTTP** — прикладной протокол модели «запрос–ответ».
- **HTML** — язык структуры веб-документа.
- **CSS** — язык правил оформления документа.
- **Шаблонизатор** — средство формирования текста документа из шаблона и данных.
- **Frontend** — часть системы, с которой взаимодействует пользователь.
- **Backend** — серверная обработка, правила и доступ к данным.

## 8. Связь лекции с лабораторной работой

Лабораторная демонстрирует базовый цикл Web без клиентского JavaScript: браузер выполняет три вида GET-запросов, NestJS выбирает данные из модели, Handlebars формирует HTML, CSS оформляет его, а изображения и видео запрашиваются по URL из MinIO. Разделение модели, контроллера и шаблонов является практическим применением MVC.
