# Контрольные вопросы ЛР-3

1. **Веб-сервис** — серверный компонент, предоставляющий данные и операции другим программам через сетевой интерфейс. Наш сервис отвечает JSON на запросы к `/api/artwork_excerpts` и `/api/users`.
2. **REST** — стиль организации API вокруг ресурсов и стандартных HTTP-методов. Адрес обозначает ресурс, метод — действие: `GET` читает, `POST` создаёт, `PUT` изменяет, `DELETE` удаляет логически.
3. **RPC** — вызов удалённой процедуры как функции с параметрами. В RPC адрес обычно называет действие; в REST основной адрес называет ресурс.
4. **HTTP-заголовки** передают метаданные запроса и ответа. Например, `Content-Type: application/json` обозначает JSON, а `multipart/form-data` — форму с файлами. `Authorization` понадобится в ЛР-4.
5. **HTTP-методы**: `GET` получает данные без изменения состояния, `POST` создаёт ресурс или выполняет операцию, `PUT` обновляет ресурс, `DELETE` удаляет его. Код состояния передаётся отдельно от JSON: `200`, `201`, `400`, `404`.
6. **Версии HTTP**: HTTP/1.1 использует текстовый формат и постоянные соединения; HTTP/2 передаёт бинарные фреймы и мультиплексирует запросы; HTTP/3 работает поверх QUIC/UDP, снижая задержки и проблемы блокировки на уровне соединения. Семантика методов и кодов остаётся общей.
7. **HTTPS** — HTTP поверх TLS. TLS шифрует обмен, проверяет подлинность сервера по сертификату и защищает данные от изменения в пути. В локальном показе используется HTTP; при публикации нужен HTTPS.
8. **OSI ISO** — семиуровневая модель сети: физический, канальный, сетевой, транспортный, сеансовый, представления, прикладной. IP относится к сетевому уровню, TCP/UDP — к транспортному, HTTP — к прикладному; TLS расположен между прикладным протоколом и транспортом.
